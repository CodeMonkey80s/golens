golens vs gopls — Domain Comparison

golens Goal

Stateless, byte-exact structural query tool for AI coding agents. Answers: "What are the exact bytes I can overwrite?"

  • No daemon, no module required
  • Sub-5ms parse, 5.35 MiB binary
  • AST-only, no type checking
  • Deterministic JSON, half-open byte offsets

gopls Goal

IDE-quality Go language server. Answers: "What does this symbol mean?"

  • Full type checking via go/types
  • Module graph, build tags, cgo
  • Refactoring, completions, diagnostics
  • LSP protocol (line/col, UTF-16)

Core Distinction

golens ≠ "gopls lite". gopls answers "what does this mean?" (types, refs, docs). golens answers "what are the exact bytes?" (offsets, source extraction). Different questions, different consumers (IDE vs AI agent), different trade-offs.

When to Use Which

Scenario Use Why
Agent needs to edit one declaration in a large file golens Byte offsets + get = safe splice
Human in IDE wants go-to-definition, rename, completions gopls Type-aware, fast UX, rich UI
CI script validating imports/duplicates without building golens Sub-second, no module graph, exit codes
Repository with broken files, partial checkouts golens Stateless, parses what it can
Understanding call graphs, interface implementations gopls Requires type information

Architecture Notes

golens — Engine Interface (from D10)

type Bounds struct{ StartLine, EndLine, StartByte, EndByte int }
type Node struct{ Name, Kind, Detail, Receiver, TypeParams string; IsAlias bool; Bounds Bounds; Children []Node; IsGroup bool }
type Document struct{ Path, Package string; Bounds Bounds; Nodes []Node; Symbols []Symbol; Imports []string; Source []byte; Comments bool }
type Engine interface{ Parse(path string) (Document, error) }

Narrow, tree-shaped, no go/ast leakage — designed so a Tree-sitter backend could swap in, but the contract commits only to Go.

gopls — LSP + Type Graph

Built on golang.org/x/tools, uses go/types, module graph, build system integration. Stateful server with incremental analysis.
